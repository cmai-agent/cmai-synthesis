# cmai Hackathon Pack

This folder contains the submission-facing materials for `cmai`.

The project should be presented as:
- a trusted onchain community builder
- built for real onchain community building work, not a toy demo
- strongest in `trust`
- also relevant to `Agents that pay` and `cooperate`

## Core thesis

Building an onchain community involves high-trust work:
- answering users
- coordinating collaborators
- managing allowlists
- handling identity
- executing wallet actions

Most of this is still manual because teams do not trust agents with money, access, or community-facing decisions.

`cmai` exists to make that work delegatable through explicit boundaries, approval gates, auditable execution, and onchain identity.

Live public presence: `https://x.com/cmai_agent`

## What judges should understand fast

In one sentence:

`cmai` is a trusted AI operator for NFT collections and onchain community building that can handle support, collaborations, content, identity, and bounded wallet actions with clear guardrails and receipts.

## Why Ethereum matters

This is not a normal Web2 ops bot.

Ethereum is part of the product because the workflow depends on:
- wallet identity
- ENS
- NFT ownership and collection operations
- onchain payouts and wallet actions
- auditable receipts for what the agent did

## Partner tooling used for real product value

- `Bankr`: wallet execution layer for bounded onchain actions
- `Uniswap API`: swap and bridge flows
- `ENS`: identity and naming layer
- `OpenSea`: NFT collection and marketplace operations
